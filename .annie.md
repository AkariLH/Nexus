## 3. ENTRY POINT & NAVIGATION FLOW

**Bootstrap sequence:**
1. `app/index.tsx` → redirects to `/(auth)/splash`
2. `app/_layout.tsx` wraps all screens with: `AuthProvider` → `QuestionnaireProvider` → `AvailabilityProvider`
3. `AuthContext` checks AsyncStorage for a persisted user session
   - If found → navigate to `/(tabs)`
   - If not → stay in `/(auth)` stack
4. On entering `/(tabs)`: `QuestionnaireGuard` (via `useQuestionnaireGuard`) checks if the wellness questionnaire is complete. If not, redirects to `initial-questionnaire.tsx`.
5. Firebase service initializes push notification listeners once the user has an active partner link.

**Tab structure (post-auth, post-questionnaire):**
`Home` | `Calendar` | `Link` | `Profile` | `Settings`

## 4. API CONTRACTS (consumed from akuzuspring)

Base URL resolved in `config/api.config.ts` from the environment variable `$EXPO_PUBLIC_API_URL`.
It holds the **full** API base — scheme, host, port and the `/api` prefix, no trailing slash — and
is the single source for every platform. There is no longer a mobile/web split: web simply uses
`localhost` as the host. A missing or malformed value throws at startup with instructions; there
is no fallback host by design.

All endpoints mirror `akuzuspring` — see that project's `.annie.md` Section 4 for the full contract table. Service-to-endpoint mapping:

| Service file | Endpoints consumed |

## 9. CONFIGURATION NOTES

- `config/api.config.ts` holds no host literal. `BASE_URL` is resolved from `EXPO_PUBLIC_API_URL`, set in `NEXUSPROJECT/.env` and loaded by `make front-run`. Expo freezes the value into the bundle at build time, so a change requires `npx expo start -c`.
- `app.json`: Android package `com.nexusapp.pareja`. `usesCleartextTraffic: true` enabled — required for HTTP to local backend (must be removed before production with HTTPS).
- New Architecture enabled (`newArchEnabled: true`). React Compiler experiment enabled.
- TypeScript strict mode enforced. Path alias `@/*` → `./`.
- The API host lives in `NEXUSPROJECT/.env` as `EXPO_PUBLIC_API_URL`, never in source. Note that `EXPO_PUBLIC_*` variables are **inlined into the bundle and readable in the APK** — they are public by construction and must never carry a secret.

## 10. ARCHITECTURAL CONSTRAINTS & FINDINGS

- **Auth token now attached to every request (fixed 2026-10-05).** `services/api.client.ts`'s request interceptor reads the JWT via `utils/authToken.ts` (AsyncStorage-backed) and sets `Authorization: Bearer <token>`. `AuthContext.login(userData, token, tokenExpiresAt?)` persists the token on sign-in; `logout()` clears it. The only call site is `app/(auth)/login.tsx` — `LoginResponse.token`/`tokenExpiresAt` come from the backend's `/auth/login`. See `utils/authToken.test.ts`, `services/api.client.auth-header.test.ts`, `context/AuthContext.test.tsx`.
- **The backend still emits absolute URLs with its own host compiled in.** `LinkService.java:172,206` builds the partner avatar as `http://<host>:8080/api/profile/{id}/avatar`. The client mitigates this in `rebaseApiUrl` (`config/api.config.ts`), called from `app/(tabs)/link.tsx`, but until the backend returns a relative path every host change still has to pass through that function.
- **QuestionnaireContext caches completion status in AsyncStorage.** If the status changes on the backend (e.g., admin reset), the client cache will be stale until explicit invalidation. This is an eventual-consistency gap to be aware of when building admin tools.
- **`externalCalendar.integration.service.ts` handles RRULE parsing on the client.** This duplicates logic that also exists in `akuzuspring`'s `AvailabilityService`. These two parsers must be kept in sync — a divergence will cause availability mismatches between what the client displays and what the backend calculates.
- **Firebase listeners are conditionally initialized** (only when user has an active link). Any push notification feature must account for this initialization gate.
- **`usesCleartextTraffic: true`** in `app.json` exposes all API traffic unencrypted on Android. This is a hard blocker for any production release.
- **`manipulateAsync` (expo-image-manipulator v14) is deprecated.** `processProfilePhoto` in `utils/imageProcessor.ts` uses it intentionally — migration to `ImageManipulator.manipulate()` (fluent API) is deferred. Flag for a future standalone task.
- **Profile photo size check was computing decoded bytes (`base64.length * 0.75`).** This was wrong — the backend enforces raw data URI string byte length. Fixed in `[profile-photo-resize]`; the processor now checks `dataUri.length` directly.

## 11. INTEGRATION WITH akuzuspring

These two projects form a tightly coupled client-server pair. Key integration constraints:

- Any change to an API contract in `akuzuspring` (path, method, request/response shape) requires a matching update in the corresponding service file in `Nexus`.
- The `EventResponse` type in `types/` must stay in sync with the backend DTO.
- The 7 wellness dimension model must match between `PreferenceController` (backend) and `UserPreferences` (frontend types).
- Timezone handling is split: backend stores UTC, frontend is responsible for display conversion. Never move this responsibility.
